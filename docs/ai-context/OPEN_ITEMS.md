# X2RED 未完成事项和风险

更新时间：2026-08-02 10:37 +08:00

## P0：合并前必须确认

### 1. 真实浏览器端到端 smoke test

当前 CI 可以验证 Python、迁移、Node 语法和服务级测试，但不能完全证明以下真实 DOM 交互：

- 三层侧栏在所有视图加载顺序下都稳定；
- MutationObserver 不会导致持续重排或性能问题；
- 来源平台 tabs 与搜索组合正确；
- 所有 `optgroup` 下拉在刷新后保留选择；
- 语料池三个分发按钮能正确切换工作台和选中批次 anchor；
- 轻内容强制刷新能在网络较慢时准确定位版本；
- 旧版本 Minimal Zine 能重合成并正确更新图库。

需要在本机实际启动并逐项确认。

### 2. PR 仍为 Draft、尚未合并

文档创建时 PR #19 尚未进入 `main`。因此：

- `git pull main` 不会获得本轮功能；
- 本地测试必须拉取功能分支；
- 准备合并前需要重新确认 base 是否前进、PR 是否仍 mergeable、CI 是否对应最新 head。

### 3. 统一旧文档

README、根 `ARCHITECTURE.md`、`docs/WORKFLOW.md` 和部分 provider 文档仍包含早期架构描述，例如：

- 以 X 单一来源为中心；
- 简中发现使用通用搜索 API fallback；
- Minimal Zine 由图片模型直接生成完整含字海报。

这些描述与当前分支不完全一致。合并前应整体更新或明确标记历史内容，避免新模型读取冲突信息。

## P1：高价值后续工作

### 4. 把 v14 前端补丁逐步合并回主控制器

当前 `light-content-fixes-v14.js` 和 `information-architecture-v14.js` 以覆盖/增强方式修复旧控制器，能够降低大范围改动风险，但长期会形成双控制器维护成本。

后续建议：

- 将已验证逻辑合并回主要模块；
- 删除重复事件绑定；
- 给关键状态机写浏览器测试；
- 保留一个明确的状态所有者。

在没有完整 E2E 测试前，不要急于删除 v14 保护层。

### 5. Minimal Zine 视觉质量继续迭代

当前重构解决的是：

- 中文和模型图解耦；
- 边缘供应商角标；
- 文件路径；
- preview/package 同步；
- 旧图重合成。

仍需通过真实题材评估：

- 视觉锚点是否过于通用；
- 每页构图是否有足够差异；
- 旧纸、灰阶和强调色是否符合原 Skill 水平；
- 中文字号、行宽和留白是否适合公众号；
- 中央区域异常符号的人工检测或自动检测策略。

不能把“测试通过”表述成“视觉质量已经达到上游示例水平”。

### 6. 语料池到工作台的产品可见性

批次 anchor 对技术追溯有效，但前端还可以更明确地展示：

- 来源池名称；
- 批次序号；
- 本批详细来源；
- 全池记忆摘要；
- focus；
- pool revision；
- 为什么选中这些来源。

这样用户能理解工作台中的“来源”其实是一次冻结批次。

### 7. 来源规模和性能

来源 API 当前允许拉取较多记录以便前端分组。来源持续增长后，需要评估：

- 后端分页；
- 按平台服务端过滤；
- 虚拟列表；
- 来源缓存失效；
- 语料池重编成本；
- 多个工作台重复请求来源列表。

不要在数据规模尚未测量前盲目微优化，但应保留这一风险。

## P2：长期架构演进

### 8. 统一工作台路由和输入协议

理想状态下，小红书、公众号长文和公众号轻内容应共享统一的“打开工作台并选中 SourceItem/CorpusBatch”协议，而不是前端分别模拟点击和 change 事件。

可以考虑稳定的工作台导航事件或 URL state，但必须先有浏览器测试。

### 9. 结构化机器上下文自动生成

当前 `context.json` 由人工维护。未来可增加脚本从 GitHub、Alembic、配置和测试中生成易变化字段，例如：

- 当前 revision；
- 当前测试数量；
- 最新 CI；
- 当前 PR head；
- 已注册 router、平台和 Skill。

长期产品原则仍应人工维护，不能全部自动推断。

### 10. 权利和许可 UI

需要继续强化：

- MediaCrawler 非商业学习边界；
- Guizang AGPL-3.0；
- Minimal Zine MIT；
- 每条来源和媒体的权利状态；
- 发布包中的许可和来源提示。
