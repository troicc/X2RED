# X2RED 0.7：Signal-to-Story Studio

X2RED 0.7 把系统拆成两个正式闭环：

1. **信号情报闭环**：监控 → 指标快照 → 冻结评分 → L1/L2 分析 → 模式库。
2. **多 Agent 写作闭环**：总编辑 → 证据研究 → 大纲 → 写手 → 三路独立审稿 → 主编裁决 → 终稿。

整个系统继续使用 FastAPI、SQLite WAL、本地文件系统和单消费者任务队列，不要求 Redis、Celery、PostgreSQL 或向量数据库。

## Mac 更新与启动

```bash
cd /Users/EasyMaker/Documents/X2RED
git pull
./scripts/start.sh
```

打开：

```bash
open http://127.0.0.1:8787
```

数据库会自动升级到 `0006`。

## 信号台

左侧进入 **信号台**，可以添加四类监控目标：

- 作者时间线：输入 X handle，例如 `karpathy`。
- 关键词搜索：输入搜索词。
- 引用帖子：输入帖子 ID。
- 趋势：输入任意非空名称作为本地显示标识。

首次建议只添加 5—10 个真正值得长期观察的作者。作者时间线默认每 360 分钟扫描一次，也可以手动点击“立即扫描”。

### 评分

X2RED 使用四个信号：

- `R`：当前内容核心互动 / 作者最近内容核心互动中位数。
- `M`：核心互动 / 作者粉丝数。
- `V`：浏览量 / 作者粉丝数。
- `Velocity`：相邻指标快照之间每小时新增核心互动。

默认核心互动：

```text
likes + 2 × reposts + 2 × quotes + 0.5 × replies + 1.5 × bookmarks
```

首次评分会冻结：

- 作者基线样本；
- 粉丝数快照；
- 算法版本；
- 分级阈值；
- 评分证据。

后续涨赞只更新内容自身的分子和增长速度，不会用未来作品改写当时的判断。

作者基线不足 5 条时，内容标记为“基线积累中”，避免用一个样本直接判爆款。

### L1 与 L2

默认自动策略：

- T1/T2/T3 自动进入 L1 快评。
- T2/T3 自动进入 L2 深度拆解。
- L2 每天最多自动处理 5 条。

可以在 `.env` 调整：

```env
X2RED_AUTO_L1_GRADES=T1,T2,T3
X2RED_AUTO_L2_GRADES=T2,T3
X2RED_AUTO_L2_DAILY_LIMIT=5
```

L1 输出摘要、爆款因素、置信度、时效/长青判断和处理建议。L2 输出钩子、结构、受众触发点、传播机制、可复制元素、不可复制背景、写作角度和事实风险，并可沉淀为模式卡。

## 写作项目

左侧进入 **写作项目**。

### 快速模式

快速模式仍然执行完整角色链，但自动确认三个门：

1. 总编辑任务单；
2. 文章大纲；
3. 主编修改计划。

适合普通帖子或时效内容。

### 工作室模式

工作室模式会在三个关键阶段停下来等待作者确认：

1. **任务单确认**：目标读者、文章承诺、主线、必用证据、禁止主张。
2. **大纲确认**：章节职责、术语首次出现、证据分配、认知负荷顺序。
3. **修改计划确认**：三路审稿之后，决定哪些意见必须修改、建议修改或不采纳。

未经确认，不会进入下一阶段。

### Agent 角色

- 总编辑 Agent：选定唯一主线和文章承诺。
- 证据研究 Agent：整理事实、作者自测、未知项、数字和术语。
- 大纲与解释 Agent：按读者理解顺序安排内容。
- 写手 Agent：严格根据已确认产物写初稿。
- 读者代表 Agent：寻找第一屏理解障碍和读者退出点。
- 事实核查 Agent：检查数字、归属和范围扩大。
- 风格审稿 Agent：检查 AI 味、讲课味和作者身份错位。
- 资深主编 Agent：裁决三路审稿意见，形成最小修改计划。
- 终稿修订 Agent：只执行获批修改，不自由重写。

每个角色都有独立输入和结构化产物。每完成一个阶段立即写入数据库；后续模型失败不会抹掉已经完成的任务单、证据包或大纲。

## 风格实验室

左侧进入 **风格实验室**。

准备：

- 至少 3 篇、推荐 5—10 篇你明确授权的同类型原创文章；
- 1—3 篇不参与初次提炼的留出样本；
- 真实改稿反馈，例如“删掉这个句式，因为太像 AI”。

用单独一行 `---` 分隔文章。

训练流程分两次模型调用：

1. 原创样本提炼规则初稿；
2. 留出样本与作者反馈验证规则、删除错误推断并生成最终版本。

风格档案保存：

- 作者身份与读者关系；
- 事实边界；
- 语言节奏与段落习惯；
- 判断方式；
- 不同文章类型的常用结构；
- 禁用表达；
- 正反例；
- 留出验证差异和作者反馈。

同名档案再次训练会增加版本号。创建写作项目时可选择具体风格档案，写手与风格审稿 Agent 使用同一版本。

## Skill 设置

在 **模型与 Skill** 中可以分别启用、停用或选择模型：

- `intelligence.l1`
- `intelligence.l2`
- `writing.style_train`
- `writing.editor`
- `writing.research`
- `writing.outline`
- `writing.writer`
- `review.reader`
- `review.fact`
- `review.style`
- `writing.chief_editor`
- `writing.final_revision`
- 原有快速写作和视觉 Skills

关闭 Skill 后，相关任务会明确失败并保留错误，不会悄悄退化成另一个 Agent。

## 调度与成本保护

```env
X2RED_SCHEDULER_ENABLED=true
X2RED_SCHEDULER_TIMEZONE=Asia/Shanghai
X2RED_SCHEDULER_POLL_SECONDS=30
X2RED_SCHEDULER_BATCH_SIZE=20
```

每个写作项目都有预算上限和估算消耗。输入和模型配置相同的成功 Agent 运行会通过输入 hash 复用产物，避免重复付费。

## 数据安全

- SQLite 使用 WAL 模式、外键约束和 30 秒 busy timeout。
- 所有监控任务和 Agent 阶段均使用现有耐久任务表。
- 运行中的任务在应用重启后会恢复为待执行。
- 任务支持优先级、去重键、最大重试次数和指数退避。
- 最终稿仍保存为不可变 `DraftRevision`，并记录写作项目、终稿产物、角色链和风格版本。
